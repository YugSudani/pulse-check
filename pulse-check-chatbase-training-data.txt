WHAT IS PULSE-CHECK?
--------------------
Pulse-Check is a real-time server and website monitoring service that helps 
developers track the uptime, response time, and health of their websites, 
APIs, and servers. The platform sends instant alerts when services go down 
and provides detailed analytics and incident tracking.

CORE VALUE PROPOSITION:
- Real-time server monitoring with up to 30-second check intervals
- Instant notifications via push, email, SMS, and voice calls
- 50 free monitors per account
- AI-powered log analysis and summarization
- Comprehensive incident tracking and reporting

TECHNOLOGY STACK:
- Frontend: React.js with Vite, React Router, TailwindCSS-like styling
- Backend: Node.js with Express.js
- Database: MongoDB (Mongoose ORM)
- Authentication: JWT with HTTP-only cookies
- Push Notifications: OneSignal
- Email: Nodemailer
- Voice Calls: Vonage API
- AI Summarization: Groq API (LLaMA 3.1 8B)

                      SECTION 5: API DOCUMENTATION
================================================================================

BASE URL: /api (relative to server)

AUTHENTICATION ENDPOINTS:
-------------------------

POST /user/signup
- Body: { name, email, pwd }
- Creates new user account
- Response: { message, success }

POST /user/genOTP
- Body: { email, name, isForSignup }
- Sends OTP to email (5 min expiry)
- Response: { message, success }

POST /user/verifyOtp
- Body: { email, otp }
- Verifies OTP and marks user as verified
- Response: { message, success }

POST /user/login
- Body: { email, pwd, otp } (password OR otp required)
- Sets HTTP-only cookie with JWT token (7 days)
- Response: { message, success }

POST /user/logout
- Clears authentication cookie
- Response: { message }

GET /user/getMe
- Returns current authenticated user
- Response: { message, success, user }

POST /user/saveOneSignalPlayerId
- Body: { playerId }
- Saves OneSignal player ID for push notifications
- Requires authentication

POST /user/saveCallNumber
- Body: { phoneNumber }
- Saves phone number for voice call alerts
- Requires authentication

MONITOR ENDPOINTS:
------------------

POST /monitor/createMonitor
- Body: { name, url, interval, alert }
- Creates new monitor
- alert: { email: { emailAlert }, push: { pushAlert } }
- Requires authentication

GET /monitor/getAllMonitors
- Returns all monitors for authenticated user
- Response: { success, monitors }

GET /monitor/:id
- Returns single monitor by ID
- Response: { success, monitor }

PATCH /monitor/pause/:id
- Toggles monitor active/paused state
- Response: { success }

DELETE /monitor/deleteMonitor/:id
- Deletes monitor and all associated logs/incidents
- Response: { success, monitors }

PUT /monitor/editeMonitor/:monitorId
- Body: { name, url, interval, alert }
- Updates monitor settings
- Response: { success }

GET /monitor/:monitorId/response-history
- Query: ?range=5m|15m|30m|2h|6h|12h|24h
- Returns response time logs with statistics
- Response: { success, data, stats }

POST /monitor/test_alert
- Body: { monitorId, phoneNumber }
- Sends test alerts via all enabled channels
- Response: { success }

INCIDENT ENDPOINTS:
-------------------

GET /incident/getAll
- Returns all incidents for authenticated user
- Response: { success, incidents }

GET /incident/:id
- Returns incidents for specific monitor
- Response: { success, incidents }

AI ENDPOINT:
------------

POST /ai/summarizeText
- Body: { text }
- Summarizes monitoring logs using Groq AI
- Response: { status, output_summary }

                    SECTION 7: TROUBLESHOOTING
================================================================================

COMMON ISSUES:
--------------

Issue: Not receiving push notifications
Solution: 
1. Ensure browser notifications are enabled
2. Check that push notifications are toggled ON in the login page
3. Try logging out and back in
4. Clear browser cache and re-enable notifications

Issue: Monitor shows incorrect status
Solution:
1. Check if the URL is accessible from external networks
2. Verify the URL doesn't require authentication
3. Ensure your server allows HEAD/GET requests
4. Wait for the next check interval

Issue: Can't login with OTP
Solution:
1. Check spam folder for OTP email
2. OTP expires in 5 minutes - request a new one
3. Ensure you're using the correct email address
4. Wait a few minutes before requesting another OTP (rate limit)

Issue: Voice call alerts not working
Solution:
1. Verify phone number is correct with country code
2. Voice calls require Business plan
3. Check phone is not on DND mode
4. Try the Test alert feature to verify

Issue: Response time chart shows no data
Solution:
1. New monitors need at least one check cycle
2. Select appropriate time range
3. Ensure monitor is not paused
4. Refresh the page

================================================================================
                    SECTION 9: SYSTEM ARCHITECTURE
================================================================================

MONITORING WORKFLOW:
--------------------
1. Monitor Worker runs every 30 seconds
2. Fetches all active monitors that are due for checking
3. For each monitor:
   a. Sends HTTP request to URL
   b. Records response time and status code
   c. Creates log entry
   d. If status changes to DOWN:
      - Creates new incident
      - Sends email alert (if enabled)
      - Sends push notification (if enabled)
      - Makes voice call (if enabled)
   e. If status changes to UP (recovery):
      - Updates incident with end time
      - Sends recovery alerts
4. Process repeats continuously

NOTIFICATION CHANNELS:
----------------------
1. Push Notifications: OneSignal (browser-based)
2. Email Alerts: Nodemailer (SMTP)
3. Voice Calls: Vonage API (automated calls)

SECURITY:
---------
- Passwords hashed with bcrypt (salt rounds: 11)
- JWT tokens stored in HTTP-only cookies
- Token expiry: 7 days
- OTP expiry: 5 minutes
- CORS configured for cross-origin requests
